## 双定时器同频 PWM + 硬件主从触发死区（TIM1 主 / TIM2 从）

工程: STM32F103C8T6, CubeMX 6.17.0 + HAL(FW_F1 V1.8.7), MDK-ARM。
TIM1_CH1 -> PA8, TIM2_CH1 -> PA0，两者计数时钟均 72MHz。

### 实现要点
- TIM1 主: `MasterOutputTrigger = TIM_TRGO_UPDATE`, `MasterSlaveMode = TIM_MASTERSLAVEMODE_ENABLE`
- TIM2 从: `SlaveMode = TIM_SLAVEMODE_TRIGGER`, `InputTrigger = TIM_TS_ITR0`（TIM2 的 ITR0 = TIM1 TRGO）
- 启动前 `__HAL_TIM_SET_COUNTER(&htim2, (ARR+1) - N)`，收到 TRGO 后从该值继续计数，
  计到 0 的时刻比主定时器晚 N 个计数 => 固定死区/相移。
- 启动顺序：先 `HAL_TIM_PWM_Start(&htim2)` 武装（触发模式 HAL 不置 CEN，计数器等待 TRGI），
  再 `HAL_TIM_PWM_Start(&htim1)`。

### 关键结论（踩坑点，后续复用）
- **触发模式下不需要手动置 CEN**：HAL_TIM_PWM_Start 对 `IS_TIM_SLAVEMODE_TRIGGER_ENABLED`
  的定时器会跳过 `__HAL_TIM_ENABLE`，由 TRGI 启动计数器。ST 官方 LL 示例
  (F1/F4 TIM_OnePulse) 与 ST 中文社区示例均如此。手动置 CEN 反而会让计数器立即自由运行，
  破坏预置 CNT 造成的相位差。
- 触发模式只控制"启动"，**不复位**计数器（复位是 Reset Mode），这是预置 CNT 技巧成立的前提。

### 参数宏（定义在 Core/Inc/tim.h USER CODE Private defines）
PSC=0, ARR=719 (100kHz), CCR=360 (50%), N=36 counts (~500ns), 预置 CNT=684。

### 验证
arm-none-eabi-gcc (STM32CubeCLT 1.21.0) `-fsyntax-only -Wall -Wextra` 编译 main.c/tim.c/gpio.c 零警告。

### CubeMX .ioc 参数名（从 E:/STMCubeMX 数据库 db/mcu/config/TIM-STM32F1xx_Configs.xml 核实）
RefParameter `TIM_MasterOutputTrigger` -> ioc 键 `TIM1.MasterOutputTrigger`
`TIM_SlaveMode` -> `SlaveMode`；`TIM_InputTrigger` -> `InputTrigger`（不是 TriggerSource）；
`Slave_TriggerPolarity/Prescaler/Filter` -> `TriggerPolarity/TriggerPrescaler/TriggerFilter`。

## 【真正的故障根因】"没有PWM生成" = 时钟配置错误，与主从逻辑无关

用 J-Link 实测定位（PC=0x0800115E 落在 Error_Handler，TIM1/TIM2 寄存器全 0）：

- 原工程 `SystemClock_Config()` 用的是 `RCC_HSE_BYPASS`（外部**有源**时钟源），
  但本板是 **8MHz 晶振**。BYPASS 模式下 HSERDY 永远不置位 ->
  `HAL_RCC_OscConfig()` 超时 -> `Error_Handler()` 死循环 ->
  **程序卡在 MX_TIM1_Init 之前，两个定时器压根没初始化，自然没有任何 PWM。**
- 实测 `RCC_CR = 0x00055B83`：HSEON=1、HSEBYP=1、**HSERDY=0** ← 铁证。

### 修复
`SystemClock_Config()` 改成 `RCC_HSE_ON`（晶振模式），失败时自动回退 HSI
(`RCC_PLLSOURCE_HSI_DIV2` + `RCC_PLL_MUL16` = 4MHz x16 = 64MHz，F1 的 HSI 上不了 72MHz)。
修好后 `RCC_CR = 0x03035B83`（HSERDY=1、PLLRDY=1），
`RCC_CFGR = 0x001D040A`（SW/SWS=PLL、PLLSRC=HSE、PLLMUL=x9）-> SYSCLK=72MHz。

### 顺带修正的差异（对齐能跑的 F4 参考工程 PWMGenerate）
- **TIM1 的 `MasterSlaveMode` 必须是 `DISABLE`**（我最初写了 ENABLE）。MSM=1 会让 TRGO
  受 TIM1 自己的 TRGI 门控，而 TIM1 的 ITR0 指向 TIM5（F103C8 无 TIM5），TRGO 发不出来。
- 主从配置全部移入 `MX_PWM_Start_PhaseLocked()`（tim.c 的 USER CODE 1），
  放 USER CODE 区 CubeMX 重新生成不会丢；`.ioc` 已还原，不再手写主从键。
- 启动顺序对齐参考工程：启动 TIM2 通道 -> 写 TIM2->CNT -> 启动 TIM1。

### J-Link 实测确认（修复后）
- TIM2: CR1=1(CEN) SMCR=0x6(SMS=110,TS=ITR0) SR=0x5F(**TIF=1 收到过触发**)
  ARR=719 CCR1=360 CCER=1(CC1E) CNT 在递增(685->711) ✓
- TIM1: CR1=1 CR2=0x20(**MMS=010 TRGO=更新事件**) SMCR=0(MSM=0)
  BDTR=0xA000(**MOE=1**) ARR=719 CCR1=360 CCER=1 CNT 在跑 ✓
- 调试寄存器快照: main.c while(1) 里持续锁存到 `g_dbg_*`，Keil Watch 窗口可看。

## 参数定稿（20 kHz + 嵌套内缩死区 5 cnt）

用户要求：**PWM 20 kHz**，且 PA0(TIM2) 脉冲"内缩"在 PA8(TIM1) 脉冲里 ——
上升沿晚 5 cnt 开通、下降沿早 5 cnt 关断（两个下降沿相差 5 cnt）。

### 关键推导
- **频率**：ARR = 72MHz/((PSC+1)*f) - 1。20kHz → **ARR=3599**（PSC=0）。
  注意：曾一度误设 `PWM_FREQ_HZ=100000` → ARR=719，用户指出要 20kHz。
  用户手改的 `PWM_PULSE 1800` 其实是对的（对应 ARR=3599 的 50%）。
- **内缩的实现**：TIM2 整体已滞后 N，要让它"早 N 关断"必须把 CCR 再减 N，
  即 **CCR2 = CCR1 - 2N**。只减 N 只能让两个下降沿对齐，减 2N 才能形成内缩。
  → PWM_PULSE2 = 1800 - 2*5 = **1790**；PA0 高 [5, 1795)。
- TIM2_CNT_PRESET = 3600 - 5 = **3595**。

### 定稿参数（Core/Inc/tim.h）
| 宏 | 值 |
|---|---|
| PWM_TIMER_CLK_HZ / PWM_PRESCALER | 72000000 / 0 |
| PWM_FREQ_HZ | 20000 → ARR=3599 |
| PWM_DUTY_PERMILLE / PWM_PULSE | 500 / 1800（PA8） |
| PWM_PULSE2 | 1790（PA0，= PWM_PULSE - 2N） |
| PWM_DEADTIME_CNT | 5（≈69 ns） |
| TIM2_CNT_PRESET | 3595 |

### J-Link 实测确认（20kHz 版）
- TIM1: CR1=1 CR2=0x20(MMS=010) ARR=0xE0F(3599) CCR1=0x708(1800) BDTR=0xA000(MOE=1) CNT 在跑 ✓
- TIM2: CR1=1 SMCR=0x6(SMS=110,TS=ITR0) SR=0x5F(TIF=1) ARR=0xE0F(3599) CCR1=0x6FE(1790) CCER=1 CNT 在跑 ✓
